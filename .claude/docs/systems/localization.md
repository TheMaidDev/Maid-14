# Localization

How fluent localization works in this fork, why it spams the console, and how to audit/fix it. Covers content-side issues only; `RobustToolbox/` is never modified for these.

## How lookup works

`LocalizationManager.GetString` (engine, read-only) logs `Warning: Unknown messageId ({culture}): {key}` when a key is missing and **returns the input string unchanged**. Correct-looking text with console spam therefore means a failed lookup feeding already-valid text back. This fork (Corvax convention, `Content.Shared/Localizations/ContentLocalizationManager`) loads **ru-RU first — it is the default culture** — and sets **en-US as the fallback** (`SetFallbackCulture`, `/* MAID rt-update */` marker). Lookup order: ru-RU → en-US for everyone; a lookup succeeds if the key exists in either culture. So a key missing in only one culture never logs (the other resolves it, possibly showing the wrong-language text), and **only a key missing in both cultures spams** — with the warning tagged `(ru-RU)`. `TryGetString` performs the same lookup without logging, which is what probe-pattern code should use when a missing key is expected.

Entity names/descriptions are special (`LocalizationManager.Entity.cs`): `EntityPrototype.Name`/`.Description` are **already localized** via `ent-{id}` fluent messages, falling back to the raw YAML `name:`/`description:` strings. The engine resolves `.desc`/`.suffix` attributes per parent chain and logs a Fluent error when an `ent-X` message exists with attributes but no `.desc` (via `WriteWarningForErrs`; the exact wording comes from Linguini, not a literal string in the engine).

## Bug classes that spam `Unknown messageId`

- **Double localization**: passing an already-localized string (`EntityPrototype.Name`, `CargoProductPrototype.Name` which falls back to it, `JobPrototype.LocalizedName`, `MetaData(entity).EntityName`, a `GetString` result) into `GetString` again. Every lookup fails and logs. Fixed sites are marked `// MAID fix double localization`; unfixable Goobstation sites are listed at the end.
- **Missing keys**: code references a key absent from **both** ru-RU and en-US — the largest spam source. Past examples: `chat-manager-language-prefix` (called for every visible-language chat/radio message; the key was deliberately commented out in `en-US/chat/managers/chat-manager.ftl`, so the code was changed to pass an empty display instead), fork content keys that existed only in ru-RU (botany analyzer, offer-item, _Maid markings), and a batch of upstream XAML-only keys (see Audit method item 5).
- **Key typos**: wrong key text never resolves anywhere — `cmd-rmojective-*` (typo), `cmd-dungen_pack_vis` (ftl has `-success` variant), a trailing space inside a key literal (`"space-villain-game-enemy-dies-with-player-message "`). Fix code to the existing key; only add ftl when no key exists.
- **Raw human text as key**: `Loc.GetString("Wrong lavaland prototype!")` — replace with a real key plus ftl entries. Hard limit: a literal containing spaces (e.g. MedicalPatch `"No room to inject"`, XAML `{Loc Make Ghost Role}`) is not a valid Fluent id, so it can never resolve via ftl — fixing it requires editing the code; in `Content.Goobstation.*` that is off-limits, so such sites stay as accepted spam (outside `_Goobstation` they were re-pointed at proper keys, e.g. `MakeGhostRoleWindow.xaml` → `make-ghost-role-window-title`).
- **Prototype `name:` raw strings** (Pattern B from PRs #248/#254): prototype YAML `name:` with human text consumed by `Loc.GetString(proto.Name)` — point the prototype at a kebab-case key and add it to `Resources/Locale/{en-US,ru-RU}/_Maid/`.

## False alarms (verified against Linguini 0.8.1 via a test harness)

- `{ "" }` placeables (2 in en-US, 613 in ru-RU, mostly the ss14-ru translation pack): format to an empty string with **zero errors**; intentional "empty" markers. Do not mass-edit.
- ftl lines that look empty (`key =`): usually multi-line values (continuation on indented lines) or intentional empty descriptions of toolshed commands.
- YAML `description:` bare-empty or `''` in entity prototypes: raw fallback strings, never logged. `suffix: ""` is not a localized field.
- A key present in only one culture resolves silently through the other: no console error, but a ru-RU player sees English text (that is the untranslated-gap class, not spam).
- `HealthExaminableSystem` probe-lookups (`health-examinable-{prefix}-{type}-{threshold}`): missing combos are **expected** — the probe detects them by comparing output to input. Now uses `TryGetString` (`// MAID fix localization spam`), so no warnings regardless of combos.
- Tile prototype `name:` values (`tiles-*`) are consumed by pointing/mapping systems but are valid keys — no spam.

## Audit method

A full sweep checks five things (audit scripts are one-off, written outside the repo per sweep — e.g. `%TEMP%/maid-loc-audit2/`, run with `python -I audit.py <repo>`):

1. Prototype keys vs ftl: for every watched prototype doc type, extract `name:`/`code:` and verify the value exists as a fluent id in en-US **and** ru-RU, plus `marking-{id}` for markings.
2. Empty values: ftl entries whose value is truly empty (no same-line value and no indented continuation) and YAML `name:`/`description:` that are quoted-empty.
3. Code literal keys: extract every string literal passed as first arg to `GetString`/`TryGetString` and check membership in the union of en-US + ru-RU + engine (RobustToolbox locale) id sets — that union is what "missing" means for spam. Concat prefixes (`"armor-damage-type-" + x`) need their runtime suffixes checked separately.
4. Double-lookup grep: `Loc.GetString(.*LocalizedName|EntityName|entProto.Name|ProductName)`, nested `GetString(GetString(...))`, `TryGetString` immediately followed by `GetString`. Note the pattern catches `EntProtoId`-indexed `EntityPrototype.Name` too (`protoEnt.Name`) — that name is already localized.
5. XAML keys: extract `{Loc 'key'}` and `{Loc key}` from all client `.xaml` and check the same union (script `xaml_sweep.py`). `Robust.Client` `LocExtension` calls `Loc.GetString` at runtime, so XAML sites spam identically; ~1577 usages exist. Unquoted multi-word values (`{Loc Make Ghost Role}`) are invalid ids and need the XAML re-pointed, not ftl.
6. Duplicate ids: the same id defined in two `.ftl` files of one culture is a redefinition error at bundle load. A key can exist in the normal tree while someone adds a "missing key" copy into `_Maid/` — compare against the whole culture tree, not just `_Maid/` (a `_Maid`-only comparison produced several false ru-parity gaps and hid four duplicates created by the earlier sweep; all since removed).
7. Tile names: the engine tile spawn menu (`Robust.Client` `TileSpawningUIController`) calls `Loc.GetString(tile.Name)` on every registered non-hidden tile — and so does the client mapping-hotbar loader. Every `type: tile` prototype therefore needs a `name:` that resolves (or `editorHidden`/`abstract`); a nameless tile logs `Unknown messageId: ""` and a raw-text name spams per menu build. Audit all tile YAMLs (skip `abstract:`/`editorHidden:`) against the union; the RMC14 Hybrisa pack shipped ~175 such tiles (fixed: generated `tiles-hybrisa-*` keys, entries in `en-US/_Maid/tiles/tile-spawn-names.ftl`, en-only — ru clients see English via fallback, no spam). Beware single-word raw names (`floor`, `cement`): re-point them to per-tile keys — adding them as global ftl ids would "fix" spam by polluting the id space.
8. Label lookups: `LabelComponent.currentLabel` values may be raw text (`Ibuprofen 10u`) or keys with typos; `LabelSystem` map-init now uses `TryGetString` (probe, `// MAID fix localization spam`) so raw labels never log. currentLabel values written as `reagent-name-*` keys must match the reagent's real dashed key (7 typo fixes in `_Goobstation` medicine bottles).
9. Dummy-spawn init lookups: UI icon controls (`EntityPrototypeView` — F5 spawn menu rows, and elsewhere) spawn full client-side clones of the prototype; every component init runs, so any init-time `GetString(<nullable datafield>)` spams one warning per visible row. The only such site found was `IdCardComponent.LocalizedJobTitle` feeding `GetString("")` for ~150 jobTitle-less ID cards (reached via PDA `id` slots and mob Loadouts); it now returns null for null JobTitle (real keys still resolve via `GetString`, so typos keep warning). When auditing, remember a UI listing prototypes is a component-init storm, not just name lookups.

Strip `//` and `/* */` comments from C# before scanning literals — commented-out call sites otherwise false-positive (verified in practice); grep is case-sensitive, and XAML uses capital-L `{Loc ...}`, so lowercase patterns miss it. Scan all code projects including `Content.Goobstation.*` for detection; their fixes go through ftl only, never code edits. Fluent ids cannot contain spaces — raw-text keys with spaces are unfixable via locale.

`ftl` files take no comments (AGENTS.md); fixes outside `_Maid/` use MAID markers; new keys for fork content mirror the ru file layout under `Resources/Locale/en-US/_Maid/`.
