# Sound path

Tile-based sound propagation for the local player (client-only, `_Maid` folders; the server is not involved). Replaces the engine's single-raycast occlusion — and, through `ProcessStreamOverride`, the engine's whole stream update — with a weighted shortest-path model: how a sound reaches the player depends on the cheapest tile path between them and on the muffling objects that path crosses. Every loudness effect is folded into one occlusion scalar that the engine lowpass carries, so a sound is born at its final loudness and the system never writes stream volume at all.

## Pieces

- `Content.Client/_Maid/Audio/PathSound/PathSoundSystem.cs` — the whole mechanism: field building, the stream-processing override, the occlusion model, debug state.
- `PathSoundOverlay.cs`, `PathSoundOverlayCommand.cs` (`showsoundpath`), `PathSoundOverlayModeCommand.cs` (`soundpathmode`), `PathSoundDebugCommand.cs` (`soundpathdebug`) — debug tooling.
- `Content.Shared/_Maid/Audio/SoundPathWeightComponent.cs` — networked `muffle` percent (0–100) that turns an entity into a blocker with exact transmission.
- `Content.Shared/_Maid/CVars/CVars.cs` (`MaidCVars`) — all tuning under `maidsound.*`.
- `Resources/Prototypes/_Maid/Audio/sound-weights.partial.yml` — partial prototypes adding the component to upstream windows and airlocks.
- `Resources/Prototypes/_Maid/Entities/Objects/Devices/sound-emitter.yml` — `TestSoundEmitter`, beeps every 5 s for playtesting.

## Fields

Four Dijkstra fields are rebuilt over grid tiles around the local player (radius from `maidsound.path_radius`, clamped 4–32). The four roots are the tiles around the player's continuous position; receiver-side bilinear interpolation between roots keeps values continuous across tile crossings (a deliberate design decision — one root would be simpler but loses interpolation).

When `maidsound.path_detour_weight` is positive, each root also gets a **detour pass** over the same tiles with cost `1 + tileOcclusion * path_detour_weight` — a route biased toward clean tiles even when longer (with the default 6, crossing an airlock is worth ~14 tiles of detour; a wall is always bypassed when any detour exists). Empty tiles are excluded from the detour pass — vacuum carries no detour sound, and without this the pass would circumvent blockers around the ends of wall lines through space wherever that is cheaper than the blocker (the shortest pass is allowed its vacuum routes; tests seal against those). The primary pass keeps its own arrays; the detour pass fills the `*2` field arrays and reuses the settled flags and the tile-weight cache. `path_detour_weight 0` skips the second pass, and the primary pass alone already detours past walls whenever the detour is cheaper in `1 + occl` terms — the detour pass exists for *cheap* blockers (airlocks, windows) that the shortest path crosses even though a clean route runs nearby.

Cost of entering a tile is `1 + tileOcclusion`, from the anchored entities:

- an entity with `SoundPathWeightComponent` contributes `OcclFromMuffle` (`-ln(1 - muffle/100)`, so `muffle: 90` leaves a tenth of the highs) while its physics body `CanCollide` is true — open or destroyed doors drop out, welded ones stay; a door whose `DoorComponent.State` is `Opening`/`Closing` also counts even while its collision is still flipped off, since the leaf blocks the tile for most of the animation (this keeps a closing airlock's own sound muffled from the moment the animation starts — collision only flips mid-way);
- otherwise a hard fixture on `Impassable` counts as a wall (`path_occlusion_per_weight * weight_opaque`, or `weight_glass` on `GlassLayer`); fixture layers exactly equal to `AirlockLayer`/`GlassAirlockLayer` count too — airlock fixtures carry no `Impassable` bit (`AirlockLayer = Opaque | GlassAirlockLayer`), so the vanilla occlusion raycast never sees airlocks at all.

Component objects are absolute (percents, independent of cvars); heuristic objects scale with cvars. Rebuilds happen when the player's base tile, grid or radius changes, when a broadcast blocker event fires — `CollisionChangeEvent` covers every `CanCollide` flip including the mid-closing moment when a door becomes solid (which fires no door-state event), `AnchorStateChangedEvent` and `TileChangedEvent` cover built, broken and re-anchored blockers — or when `maidsound.path_cache_ttl` (2 s) expires as the fallback for anything without an event. Blocker-event rebuilds are throttled to one per 100 ms. Tile-step and event rebuilds run **on the thread pool** into a scratch buffer that is copied over the live field on the next frame update; grid, radius and door-state changes rebuild **synchronously on the main thread** — door audio is client-predicted (`PlayPredicted` → the client's forced stream processing starts the source mid-tick, the same tick the state flips), so the fields must be fresh before that tick's stream runs, and a door state change that leaves every door tile's cached weight unchanged (e.g. Closing → Closed) skips the rebuild entirely.

Tile weights are cached **per world tile in a persistent dictionary** shared by all four roots (the per-root recomputation of identical weights was the dominant rebuild cost) and copied into a window array for the passes; vacuum tiles carry an empty sentinel that also excludes them from the detour pass. The cache is invalidated per tile by the blocker events, fully refreshed when the grid changes or the TTL elapses, and a blocker-free window skips the detour passes entirely. `soundpathdebug` reports the last rebuild time.

## Per-sound values

`TryGetAudio` produces the per-source model, interpolated bilinearly across the receiver's tile corners (the source is read at its single floor tile — an interpolated source would dilute the blocker behind it: a grid-centered source lends its wall only a quarter of the blend, so sounds behind airlocks played nearly clean). A blocker belongs to the path a sound crosses, not to the tile it is born on: the source tile's own occlusion is always subtracted, so an airlock's open/close sound is audible from any distance, while a sound behind a row of closed airlocks stays silent (their tiles are still on the route). The subtraction uses the field's own window price for the source tile, not the live world weight: a door-state flip can leave the field one frame behind the world (open in the world, still priced blocked in the field), and subtracting the live weight in that frame leaked the tile's stale field price as a 1-3-tick occlusion spike (blended ~1.25 → filter +21 dB) on the door's own sound, stretched by smoothing into an audible jump halfway through opening. An earlier downhill-neighbor variant of this recovery (`PredEntrySumW`, largest neighbor `SumW`) also picked the most-blocked neighbor in airlock banks, muffling a door's own open sound with a neighboring closed door the route never crossed (`BankOwnSoundStaysAudible` pins this). In stable frames the window price equals the live weight bit-for-bit. The early self-muffle experiment — exempting the source tile only next to the player — was reversed by the user once blocker loudness loss made it silence the door two tiles away. Blending cutoffs instead of raw occlusion turns a route disagreement (two symmetric detours around a diagonal wall) into a fade instead of a silence/clean toggle. Unreachable field tiles (sealed rooms) are skipped in the blend instead of contributing a fake-clean zero. A root seeded on a blocker tile — a listener corner hugging a wall or a closed airlock — is skipped too (unless the sound itself is born on that tile): its routes start past the blocker and would cross it for free, diluting the blend of the honest roots by up to a quarter. A door-state flip can transiently overprice the source tile itself (a frame where the fixture heuristic reads the door as a wall), sending that tile's Dijkstra route the long way around while the own-tile exemption keeps the occlusion clean — the distance fold then eats the phantom detour as an audible dip on the door's own sound. When a root's route is grossly longer than the straight line (more than `DirectEntrySlack` = 4 tiles), `DirectEntry` also prices the entry from each downhill neighbor of the source tile and keeps the cheapest: the predecessor of a sane route reproduces it exactly, and the distorted one collapses to the honest direct entry.

Per root, the detour field's value is blended in only when its fully folded value (muffling, per-tile loss and the straight remainder, the same formula the override applies) is strictly better than the primary's **and the detour takes at least four extra hops past the direct route** — clean corridors (both paths equally clean), sealed rooms (no detour reachable) and short bypasses through neighboring open doors of an airlock bank keep their exact primary values, so a closed blocker is never defeated by a side step. The blend mixes 15% of the detour's `e^-occl` gain into the primary's and scales the path metadata (hops, past) by the same shares, so the distance-loss fold interpolates between the two routes; the flag lands in `DebugEntry.Detoured` for the overlay and dump.

## The stream-processing override

The system subscribes `AudioSystem.ProcessStreamOverride`, which replaces the engine's whole `ProcessStream` body for every stream. The handler replicates the engine branches — first-frame start, global-sound handling, other-map muting, `Volume = Params.Volume` (the system never writes stream volume itself, so Params stays pristine forever and the per-tick reset always restores vanilla), the max-distance clip (`sqrt(d² + z²) > MaxDistance`, z from `audio.z_offset`), position and velocity — and replaces only the occlusion step:

`occl' = occl·(1 + path_occlusion_loss_db / 0.8686) + (pathLen + past)·path_loss_db_per_tile / 0.8686`

The engine lowpass attenuates 0.8686 dB per occlusion unit, so folding the loudness terms into the occlusion makes the filter carry the entire model. `occl` is the blended path muffling (with the past-tile decay behind the last blocker); the distance terms are the per-tile loss (`path_loss_db_per_tile`, the hearing-radius lever: with the fold, `path_loss_db_per_tile·1.727` dB per tile — a clean route fades to silence around 35–40 tiles) and the blocker loudness loss (`path_occlusion_loss_db` per occl unit — any route crossing a closed blocker is slammed toward silence). The result is clamped to 400. Doppler velocity is intentionally not replicated (the engine branch is skipped).

This placement is load-bearing: client-predicted sounds (`PlayPredicted` — doors, footsteps, melee; ~300 call sites) start their source mid-tick inside `PlayPredicted`, and the forced stream processing commits their birth volume before any content code after the call can run. With the override, that same forced call computes the full model from the fresh fields — a far door's close sound is silent from its first sample. Nothing content-side can run before that point otherwise.

Beyond the field radius the handler reads the field at the edge tile along the listener→source ray and adds a raycast (`IntersectRayPenetration`, mask widened by `GlassAirlockLayer` since airlock fixtures carry no `Impassable` bit) over the remainder, with straight-line distance folded in; a source on another grid skips the field entirely (foreign coordinates would map onto an arbitrary field tile) and takes the plain raycast. Raycast penetration is vanilla meters and is converted to field units (`Round(pen / tileSize)` walls × the wall heuristic) so the fallback speaks the same scale as the field; grazing rays under half a tile stay free.

Per-stream smoothing: the computed value is lerped in a `ConcurrentDictionary` (the handler runs on parallel audio-job threads when ≥ 5 streams exist; races are benign — a lost update just converges one tick later), so rebuild steps fade over a few ticks instead of snapping the filter. Stale entries are swept from the frame update.

## Invariants and failure modes

- A directed `(component, event)` subscription pair allows exactly one handler per client (`EntityEventBus` throws on duplicates), and a failed connection attempt re-runs system `Initialize` on the next join — so this system holds no directed subscriptions; the smoothed-entry dictionary is swept lazily instead of via `ComponentShutdown`.
- Broadcast subscriptions to one event must all agree on by-ref or by-value (`EntityEventBus` throws on a mix during join-time re-initialization, which fails the join). Engine struct events this system listens to — `TileChangedEvent`, `AnchorStateChangedEvent`, `CollisionChangeEvent` — are by-ref and keep `ref` handlers; class events like `DoorStateChangedEvent` are by-value.
- The handler never mutates main-thread-only state: field reads are pure (a read racing the main-thread rebuild can only miss a tile for one tick — benign fallback to the raycast), the smoothed dictionary is concurrent, and `AudioComponent` volume/gain/position/occlusion writes are what the engine itself does from the same job threads.
- `ProcessStreamOverride` supports a single invocation target — this system must remain the only subscriber.
- Sounds the engine never occludes are out of scope: `AudioFlags.NoOcclusion` (grid audio such as the FTL rumble) gets `Occlusion = 0`, global sounds skip occlusion entirely, and out-of-range sounds are gain-clipped by the replicated max-distance branch.
- The model only shapes what reaches the engine lowpass — the vanilla loudness chain sits on top and the overlay does not show it: a source's base volume (`Params.Volume`, often −6…−20 dB), OpenAL's linear distance rolloff (rolloff 1 / refDist 1: −9 dB at 10 tiles, gain 0 at the clip point) and each sound's own `MaxDistance` (`AudioParams.Default` = `SharedAudioSystem.DefaultSoundRange` = **15 m**) can all silence a sound the field marks clean. Beyond `MaxDistance` the handler hard-mutes the stream before consulting the model, and a max-distance clip never ran `GetPathOcclusion` in the past — the marker kept a stale in-range value until the clip branch started recording `DebugEntry`s with `Mode = MaxDistanceClip` (red `MD d:>…` markers). Per-sound estimates of the full chain (`engineGainEst`, `estLoudnessDb`) and every parameter involved are in the `soundpathsnap` dump.
- `maidsound.*` cvars are deliberately **not** `ARCHIVE`: they are session-only, so a stale value saved by an older build can never override the code defaults (that override silently reverted tuning twice). Permanent tuning = change the defaults in `CVars.cs`.

## Debug

`showsoundpath` toggles the overlay; `soundpathmode <off|field|numbers|all>` picks what is drawn: tiles colored by audibility (green ≥ 0.7 clean, yellow muffled, red barely, grey no path), per-tile percentages, sound markers colored by `e^-filter` with their `o:` (path occl), `f:` (folded filter) and `v:` (source base volume dB) values — a red `MD d:…>…` marker instead means the engine hard-muted the stream past the sound's own `MaxDistance` before the model was consulted — and a legend with all tuning values plus the caveat that tiles, percentages and markers show the model only, with source volume, rolloff and `MaxDistance` applied on top. In field/all modes each sound also draws **how it reaches the player**: the reconstructed route as translucent tile strips plus a polyline from the source to the listener — orange for the shortest route, cyan for the detour when it participates (`TryGetRoute` walks the fields downhill from the sound's tile to the dominant root, no stored parents needed). Tile colors still reflect the primary route only; the routes and markers carry the blended truth. `soundpathdebug` dumps the last filter values per sound (`*detour` marks blended ones, `*MD` clipped ones). `maidsound.path_smoothing` sets the fraction of the gap to the raw filter value closed per call; `maidsound.path_detour_weight` scales blocker cost on the detour pass (0 = detours off); `maidsound.path_enabled false` unsubscribes the override and reverts to engine behavior entirely.

`soundpathsnap [label]` writes a full JSON snapshot of the state into the client user data dir (`soundpath/snap-<timestamp>-<label>.json`; the command prints the absolute path) for offline analysis: effective cvars (including `audio.z_offset`, raycast length, occlusion mask and master gain), listener position, field state, the whole tile-weight cache, all four root fields (reachable tiles only, detour values null when unreachable), every live `AudioComponent` with its engine parameters (`FileName`, base/applied volume, gain, `MaxDistance`, rolloff, ref distance, clip verdict, a mirrored `LinearDistanceClamped` gain estimate and a full-chain `estLoudnessDb`), the model verdict per stream, per-root breakdowns (occl/hops/past per pass, detour share decision with both folded `f1`/`f2` values), reconstructed routes and a ring of the last 128 per-stream model decisions for catching birth-time transients.

The shipped cvar defaults are the play-tested preset: `weight_opaque 8`, `path_occlusion_per_weight 15` (a wall tile costs 120 occl units → practical silence behind walls), `path_occlusion_loss_db 15` (a route crossing a closed blocker is slammed toward silence, while a genuinely clean corridor keeps the hearing radius), `path_loss_db_per_tile 1.5` (≈ 35–40-tile hearing radius), `path_radius 25`, `path_detour_weight 6`.

## Prior art

The same problem space, for comparison: Barotrauma vanilla compares the source's and listener's hulls (plus a water path) and applies a lowpass — coarse, per-hull rather than per-tile; the community [Soundproof Walls mod](https://github.com/Plag0/Soundproof-Walls) ramps a cutoff per obstruction between hulls. Thief and The Dark Mod (Doom 3) build a **portal graph where doors are dynamic portals** — opening one changes the propagation graph, exactly what this system's door-event rebuilds do. CS:GO's 2017 audio overhaul occludes "through and around materials" with traces — our beyond-field raycast fallback is the same trace, and the path model adds the around-routing. Academic work (portal propagation caches, [Project Triton](https://arxiv.org/abs/2107.11548)) treats doors-as-dynamic-portals as the hard part and solves it the same way we do: recompute the propagation data on geometry change. Where this system differs: the whole loudness model is folded into the lowpass occlusion scalar (most engines drive a separate volume/attenuation parameter), which is what makes predicted sounds born at their final loudness.

## Testing

The model is deterministic and covered by integration tests (`Content.IntegrationTests/Tests/_Maid/PathSoundTest.cs`; run with `dotnet test Content.IntegrationTests/Content.IntegrationTests.csproj -c DebugOpt --filter "FullyQualifiedName~PathSoundTest"`). Each test builds a sealed one-tile-wide corridor east of the player, places blockers, and asserts the folded filter value against the analytic expectation — blockers minus the past-decay, folded, plus the per-tile distance fade. The contract matrix (defaults): a clean 10-tile route ≈ 17 occl units (audible); one closed airlock with the source five tiles past it ≈ 41 (muffled — the past-decay eats part of the muffle); five closed airlocks in a row ≈ 220 (silent); a source born on an airlock tile is exempt from its own tile and stays audible; airlock + glass airlock ≈ 88; a window ≈ 26; a wall in a sealed room ≈ 400 (silence); sources past the field edge fold the straight remainder; an airlock with a clean detour carved through gates in the flanking wall sits well below the primary expectation, and `path_detour_weight 0` returns it to the exact primary value (sealed scenarios are untouched by detours either way). Rough bands for hand-checking: filter < 40 = audible, 40–150 = muffled-to-near-silent, > 150 = silent. Current status, the door-audio timing contract and the continuation plan live in `.claude/docs/systems/sound-path-tests.md`.
