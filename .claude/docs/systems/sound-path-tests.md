## Раунд 29 (21.11): «шлюз глушит свой же звук» — трансиентный обход маршрута + DirectEntry — 10/10

Жалоба: шлюз, не успев полностью открыться, глушит собственный звук (маркер `o:1,32 f:4,6 v:-54` у шлюза в тайле от игрока). Два снапшота (`soundpathsnap airlock`) + ring 1024 поймали глушение живьём: **raw скачет 1.71 → 21.96 на 1-6 тиков при каждом цикле откр/закр** (uid'ы 1615/1617/1621/1623/1625, dist 0.98). Декод: 21.96 = ~12.7 ЧИСТЫХ тайлов пути (12.7×1.727) — маршрут Дейкстры к тайлу шлюза на тик перестройки уходит «в обход» (~13 тайлов по коридору), хотя прямой вход — 1 хоп. Причина: трансиентная переоценка веса самого тайла шлюза (кадр, где эвристика фикстур читает дверь как стену 120 вместо 2.303 компонента) — selfW отменяет вес (occl остаётся 0), но ГЕОМЕТРИЯ маршрута (hops) съедается потерей на дистанцию; сглаживание 0.15 растягивает провал до ~0.3-0.5с (f до 9.5). v:-54 из скрина = слипшиеся подписи двух маркеров (light_hum f:4.58 → «f:4,6», v:-15 рядом с v:-5); квары в снапшоте — все дефолтные.

ФИКС `DirectEntry` (27527d10e9, константа `DirectEntrySlack` = 4): если маршрут корня длиннее прямой больше чем на 4 тайла (сигнатура искажения), сравнивается вход в тайл источника с каждого downhill-соседа (`dist[n] < dist[idx]` — предшественник маршрута или тайл ближе к слушателю); candOccl = `SumW[n] − decay·candPast` (свой тайл исключён целиком), берётся дешевле по fold. Честный маршрут воспроизводится кандидатом побитово → тесты не меняются; искажённый схлопывается в прямое вхождение (raw 21.96 → 1.71). ⚠️ Ловушки при реализации: (1) unrestricted-кандидат по ВСЕМ соседям нашёл эксплойт past-decay (0.3×18.27 = 5.48 ед/тайл > 1.727 дистанции — «длинный past» ДЕШЕВЛЕ: SingleClosedAirlock 40.57 → 36.51 через соседа ПОЗАДИ источника с past 7) — лечится downhill-ограничением; (2) без гейча `len − dTiles > slack` падал FiveAirlocksRowSilence (219.79 → 46.34: DirectEntry ломал бленд корней с вакуумными маршрутами) — гейч по сигнатуре патологии оставляет легитимные дальние маршруты нетронутыми. Ring 128→1024 + мёртвые стримы держатся в снапшоте ~10с (2c158f1aab) — именно это поймало трансиент во втором снапшоте.

## Раунд 28 (21.11): «овелей дурит» — ванильная цепочка громкости + снапшоты — 10/10

Жалоба: оверлей показывает «должно быть слышно» (зелёные/жёлтые тайлы 22-33%, маркеры `o:0.00 f:9.7` у шлюзов), а звук на этих клетках реально не слышен. Диагноз (по коду, без плейтеста): **овлей показывает ТОЛЬКО дельту модели**, а поверх неё работает ванильная цепочка громкости, которой оверлей не видел:

1. **`AudioParams.Default.MaxDistance = SharedAudioSystem.DefaultSoundRange = 15`** — звук без явного WithMaxDistance движок ХАРД-мьютит дальше 15.3 м (`sqrt(d²+z²)>MaxDistance → Gain=0`) ДО обращения к модели. Квары `maidsound.*` этот потолок НЕ поднимают (RA0002 — писать Params контенту нельзя). Круги юзера на скриншоте — дальние шлюзы за пределом 15 м у дефолтных звуков.
2. Базовая громкость `Params.Volume` (часто −6…−20 дБ) + линейный роллофф OpenAL (rolloff 1, refDist 1: −9 дБ @10 тайлов, 0 на клипе) тоже съедают слышимость невидимо для оверлея.
3. **Ловушка стейла**: MD-клип-ветка раньше не писала `_debug` → маркер МОГ показывать старое in-range значение модели (`o:0.00 f:9.7`) при реально замьюченном стриме. Теперь клип-ветка пишет DebugEntry с `Mode=MaxDistanceClip` → маркер краснеет, метка `MD d:21>15`.

Фиксы/инструменты (коммит кода + коммит доков): маркеры с `v:` (базовая громкость) и красным `MD`; легенда с кавеатом «tiles/%/o:/f: = model only»; свип мёртвых записей `_debug`; ring 128 последних решений per-stream; **`soundpathsnap [label]`** — JSON в юзер-дату (`soundpath/snap-*.json`, абсолютный путь печатается): все квары (вкл. z_offset/raycast/master), listener, состояние поля, кеш весов тайлов, 4 корневых поля (только достижимые; детур null), КАЖДЫЙ живой AudioComponent (FileName, base/applied volume, gain, MaxDistance, rolloff, refDist, verdict клипа, зеркальный `engineGainEst` LinearDistanceClamped, `estLoudnessDb = base + 20log10(gain) − 0.8686·smoothed`), модельный вердикт, per-root breakdown (occl/hops/past обеих Дейкстр, share, f1/f2), маршруты, ring. Этим файлом декодируется любая «слышу/не слышу» ситуация без плейтеста.

`EntityUid` в этом RT — поле `Id` (int), НЕ `Value`; `MathF.Clamp` не существует (Math.Clamp); ⚠️ **System.Text.Json в клиентском контенте ЗАПРЕЩЁН sandbox type-check'ом** (подтверждено живьём: `Sandbox violation: Access to type not allowed: JsonSerializer/JsonSerializerOptions` + `System.IO.Path` → TypeCheckFailedException → клиент падал при загрузке модулей). Переписано на ручной `JsonBuilder` (StringBuilder, float через `ToString("0.####").Replace(',', '.')` — локале-стойкий десятичный разделитель); `FileMode`/`StreamWriter`/`ResPath` whitelist проходят. Коммит 8808df1db8, suite 10/10, клиент перезапущен — typecheck чист.

## Раунд 24 (21.11): multi-path + визуализация — 10/10

1. **`maidsound.path_detour_weight`** (default 6, CLIENTONLY, без ARCHIVE): 0 = детур-проход не строится (поведение побитово как раньше).
2. **Детур-проход исключает пустые тайлы** (вакуум не несёт детур-звук) — без этого детур-поле находило вакуумные обходы за торцами стен дешевле пересечения шлюза, и бленд ломал герметичные тесты (219→49, 81→44).
3. **Бленд в `TryGetAudio`**: per-root, решение по полным свёрнутым значениям (`f = occl·kOccl + (hops+past)·kLoss + straight·kLoss`), только при `f2 < f1 − 1e-3` **и обход ≥4 тайлов длиннее прямого пути** (короткие обходы через соседние открытые шлюзы банка не побеждают закрытую дверь — жалоба юзера раунда-26); гейн-бленд 15% (было 50% — «прекрасно слышно» через банк), метаданные линейно.
4. **Визуализация**: `TryGetRoute` (спуск по `_dist`/`_dist2` от тайла источника к доминантному корню, без хранения родителей) + оверлей рисует маршруты: оранжевый = кратчайший, циан = обход; `DebugEntry.Detoured` + `*detour` в `soundpathdebug`.
5. **Тест DetourAroundBlockerRaisesAudibility** — главная ловушка геометрии: ворота в стенном ряду дают ОБХОД ДОШЕВЛЕ шлюза для primary (9 < 9.303) → primary сам обходит, детур-поле не нужно; северные корни (сидят в стенном ряду) дополнительно утекают в вакуум y=2 (primary разрешает пустые тайлы). Рабочая геометрия: ворота ДАЛЕКО (2,1)/(8,1) + полоса y=2 на [2..8] → primary-обход 13-15 hops (> 9.303, блокирован у всех корней), детур-проход берёт обход (шлюз = 19.8) → бленд у всех корней; `path_detour_weight 0` возвращает точный primary-аналитик.

## Раунд 25: рецепт «быстро поднять радиус слышимости» (консультация, без кода)

Главный рычаг `maidsound.path_loss_db_per_tile` (дБ за тайл пути, default 1.5) — мгновенно в консоли клиента без пересборки поля (читается при каждом расчёте фильтра): 1.5 ≈ 40 тайлов слышимости, 1.0 ≈ 60, 0.75 ≈ 80 (обратно пропорционально). Второй квар `maidsound.path_radius` (25, clamp 4–32) — радиус поля; за краем модель деградирует до clamp+рейкаст, не умирает. ⚠️ Жёсткий потолок — ванильный `MaxDistance` конкретного звука: движок мьютит независимо от модели (писать MaxDistance контенту нельзя, RA0002). Постоянная настройка = дефолт в `CVars.cs` (квары session-only, не ARCHIVE).

## Раунд 26: перф — «расчёт звука убивает ФПС» → фоновая пересборка + кеш весов (f63dff26af + c7296459a1)

Причина жалобы: мульти-путь ×2 Дейкстры + поднятый юзером `path_radius 32` = ~20-28 мс пересборка на каждый шаг тайла при ходьбе на main-потоке = фризы. Решение:

- **Постоянный кеш весов** `Dictionary<Vector2i, float> _tileWeightCache` по мировым тайлам (−2 = вакуум-сентинел, он же детур-исключение; раньше веса дублировались ×4 корня на каждую пересборку + TryGetTile на каждый relax). Инвалидация per-tile от событий: `CollisionChangeEvent.BodyUid`, `AnchorStateChangedEvent.Entity`, `TileChangedEvent.Changes[].GridIndices`; дверное событие НЕ несёт entity (directed, а подписка broadcast) → помечаются тайлы всех дверей запросом `EntityQueryEnumerator<DoorComponent, TransformComponent>`. Полный refresh словаря раз в TTL 2 с — страховка от дыр (удаление стены без события).
- **Фоновая пересборка**: шаг тайла / события / TTL → `Task.Run` → worker строит 8 Дейкстр в scratch-бандл (`FieldBuffers`, 2 штуки) → swap `Array.Copy` в live **в начале следующего FrameUpdate**. Worker — чистая работа с массивами: веса пре-вычислены в окно на main, EntMan не трогается; radius/baseTile передаются параметрами (не читать скаляры — main может их сменить в swap). Синхронно остались: первый билд, смена грида/радиуса, дверные события (born-quiet требует поле в тот же тик).
- **Door-skip**: `DoorWeightsUnchanged()` сравнивает вес каждого дверного тайла кеш-vs-мир — Closing→Closed не триггерит пересборку.
- Детур-проходы пропускаются на полях без блокеров (скан окна); троттл event-rebuild 50→100 мс (двери в обходе); `soundpathdebug` показывает `rebuild: X.X ms` (sync — Stopwatch; worker — `Stopwatch.GetTimestamp`, общий Stopwatch не thread-safe).

Готчи (кусали в этом раунде): sizing бандлов = `fieldCount × RootCount` + heap `count×4` на проход (иначе ArgumentOutOfRangeException в Array.Fill); **swap готовой сборки — в начале FrameUpdate, до ветки триггеров** (иначе стоя на месте поле обновляется только по TTL 2 с → 7/10 в первом прогоне); **`volatile` поле в bundle запрещено sandbox type-check'ом Robust** («Sandbox violation: IsVolatile» → клиент падает при загрузке модулей, TypeCheckFailedException) — обычный bool достаточен при чтении раз в кадр; исключения в Task.Run глотаются → флаги сбрасываются, условие ретраит; оба scratch busy → пост откладывается на кадр. Итог: main платит ~0.5 мс вместо 20-28 мс; тесты ускорились ~50× (SingleClosedAirlock 32 с → 340 мс).

## Раунд 27: банк-обход — «закрытый шлюз + 2 открытых позади = прекрасно слышно» (e4c46a75c1)

Декод скриншота: `o:0.78-0.97` при чистом закрытом шлюзе (2.303) = детур-бленд сработал. Геометрия — 3-широкий банк шлюзов (закрытый в центре, ОТКРЫТЫЕ по бокам): обход через открытых соседей = +2 тайла, идеально чистый → детур-проход (K=6: шлюз 14.8 vs обход 8) выбирал его → гейн-бленд 50/50 → occl_eff = −ln(0.5·e^−2.003+0.5) ≈ 0.6-1.0 → 23-33% слышимости. Не баг кода, а агрессивные дефолты мульти-пути. Фикс (2 константы, без кваров): **`MinDetourExtraHops = 4`** — бленд только при ≥4 лишних тайлов past прямого маршрута (банк-обход +2 gated → дверь глушит чисто) и **`DetourShare 0.5 → 0.15`** — длинный обход (+6-15) даёт «тихий звук» (~5-10%), не 30%. Детур-тест (+8 hops) детерминированно 42.42 < 43.68 ✓. Крутилки на будущее: если банк всё ещё течёт → `MinDetourExtraHops` вверх / `DetourShare` вниз; длинные обходы слишком тихие → `DetourShare` вверх; фича целиком off → `path_detour_weight 0`.

## OpeningAirlockRaisesAudibility — причина найдена и устранена (20.11, вторая сессия)

Падение было **чисто тестовой багой**: в середине теста стоял лишний `await pair.CleanReturnAsync()` — пара утилизировалась до второго `SetDoorState`, поэтому `ToClientUid` не находил дверной entity («Failed to resolve MetaData … 12752»). Никакого PVS-делита и lifecycle-заговора. Заодно: wait-цикл `SetDoorState` ждал флипа клиентской коллизии, которого по контракту не бывает (см. ниже) — 60 холостых итераций на каждый Open; условие сведено к совпадению стейта.

### Важные открытые факты (проверено диагностикой, пригодится)

- **Сетевое изменение стейта двери НЕ флипает клиентскую коллизию**: клиент получает `State = Open` через AutoHandleState, но `PhysicsComponent.CanCollide` остаётся true (SetCollidable вызывается только в реальном потоке двери/предсказании). Модель консистентна с физикой клиента — контракт задокументирован в тесте (утверждение «opened but solid on client»).
- Следствие для продакшена: **звуки чужих дверей (сервер-реплицированные) не продырявливают глушение при открытии** — модель молчит, пока коллизия не флипнулась на клиенте. Это ХОРОШО для юзера (ранее «о чудо» поднимало слышимость), но означает: тихое открытие чужой двери будет глухим до реального CanCollide-флипа (OnPartialClose). Потенциальный follow-up: подписка на клиентский DoorComponent state-delta → явный SetCanCollide-флип на клиенте (если юзер захочет, чтобы чужие двери «продырявливали» звук сразу).
- Аналитические ожидания должны учитывать **past-decay** (`occlR = max(0, Σblockers − 0.3·past)`) и **clamp occl на −ln(1e-9) ≈ 20.72** (helper `Expected()` уже делает).
- Готчи инфраструктуры: клиентский локальный моб НЕ телепортируется серверным SetAttachedEntity-координатам (клиент-авторитетная физика) — телепортировать на клиенте тоже (`map.CGridUid`); `GlassAirlock`-прототипа нет, есть `AirlockGlass`; `client.System<ServerDoorSystem>()` кинет UnregisteredTypeException — использовать алиасы ClientDoorSystem/ServerDoorSystem; серверные uid нельзя читать клиентскими EntMan-методами в WaitAssertion (KeyNotFoundException → пара dirty).

## Состояние и план продолжения (следующий топик)

Состояние: раунды 21-28 закоммичены (`48a6067301` selfW → `f07d82b995` smoothing → `7452530612` тесты → `24ab62c985`+`0c8e16b04e` multi-path/визуализация → `f63dff26af`+`c7296459a1` перф → `e4c46a75c1` банк-обход → раунд-28 снапшоты/MD → `8808df1db8` снапшот без STJ), suite 10/10, всё собрано DebugOpt, сервер+клиент запущены из worktree. Пересборка при запущенной игре = сначала taskkill (MSB3027).

**Плейтест-чеклист юзера (за юзером, в следующем топике):**
1. ФПС: ходьба по станции, двери, толпа — фризов быть не должно; `soundpathdebug` показывает `rebuild: X.X ms` (это worker-время, main платит ~0.5 мс). Для замеров ФПС оверлей выключать (`showsoundpath` off) — numbers-режим рисует сотни DrawString за кадр.
2. Банк шлюзов (закрытый в центре + открытые по бокам): за закрытым — глухо; маркеры `o:` ≈ 2.0, не 0.7-1.0.
3. Дальний обход (источник за закрытым шлюзом, вокруг длинный чистый коридор): тихий звук (~5-10%), циановая линия обхода на оверлее.
4. Герметичная стена / ряд шлюзов: тишина без изменений.
5. Если нужен больший радиус слышимости: `maidsound.path_loss_db_per_tile` вниз (мгновенно) + `path_radius` до 32. ПОМНИТЬ: ванильный потолок — MaxDistance конкретного звука (дефолт 15 м); квары не поднимут звук дальше его собственного MaxDistance, красные MD-маркеры показывают именно это.
6. «Слышу/не слышу не то, что показывает оверлей» → консоль `soundpathsnap <метка>` → прислать файл из юзер-даты (путь печатается в консоли) — декод полной цепочки громкости по каждому звуку.

**Крутилки, если плейтест не устроит:**
- Банк/байпас всё ещё течёт → `MinDetourExtraHops` 4→6 или `DetourShare` 0.15→0.05..0.1 (константы в PathSoundSystem.cs).
- Длинные обходы слишком тихие → `DetourShare` вверх (0.15→0.25..0.3).
- Мульти-путь целиком off → `path_detour_weight 0` (поведение побитово как до раунда-24).
- Постоянная настройка — дефолты в `CVars.cs` (квары session-only, не ARCHIVE).

**Известное поведение (НЕ баг, задокументировано):** чужие двери не флипают клиентскую коллизию по сетевому стейту (follow-up: клиентский флип CanCollide по state-delta); ванильный MaxDistance капает дальние звуки; стены с чистым обходом рядом уже прозрачны через primary-Дейкстру (round-24, осознанно); vacuum-обходы разрешены primary и исключены только в детур-проходе.

**Пуш:** ребейз `sound-path` на `origin/main` (39↔4, main вобрал #278) → прогон suite → пуш.

**Идеи на потом (не начаты):** «тайл источника пополам» = nearest-center pick (строгое неравенство 0.5, НЕ MathF.Round, НЕ blend — раунд-11; юзер не подтвердил); per-path полный fold в гейн-домене (физически честные энергии путей — сейчас mix в occl-домене + пост-fold); sub-tile геометрия фикстур (большой проект).
