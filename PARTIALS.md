# Partial-прототипы

**Partial** — это «заплатка» для готового прототипа. Вместо того чтобы копировать весь прототип или править оригинал, ты пишешь только то, что хочешь изменить. Игра сама наложит заплатку поверх оригинала.

## Где писать

Partial работает только в двух местах:

- файл с именем `что-угодно.partial.yml` — в любой папке `_Maid`;
- любой файл в `Resources/Prototypes/_Maid/Override/` — там **все** файлы считаются partial.

В `Override` повторяй путь оригинала. Оригинал `Prototypes/Entities/Objects/foo.yml` → заплатка `Prototypes/_Maid/Override/Entities/Objects/foo.yml`.

Оригинал (файл вне `_Maid`) править нельзя.

## Простой пример

Хотим заменить звук питья у бутылки. Пишем **только** это:

```yaml
- type: !PartialOnly entity
  id: BaseFoodCondimentBottle
  components:
  - type: Drink
    useSound:
      path: /Audio/_Maid/Override/Items/drink.ogg
```

Что здесь важно:

- `!PartialOnly` перед `entity` — «меняй, только если такой прототип уже есть». Если оригинал пропадёт, заплатка тихо отключится, а не создаст кривой новый прототип. **Пиши его всегда.**
- `id` — id оригинала.
- Остальные поля пишем те, что меняем. Всё, чего нет в заплатке, остаётся как в оригинале.

## Как складываются поля

| Что пишешь | Что будет |
|---|---|
| Обычное значение (`name: Новое`) | заменяет старое |
| Компонент, который уже есть | меняются только указанные поля |
| Компонента нет | добавляется целиком |
| Список (`tags:` и т. п.) | твои элементы **добавляются** к старым |

## Удаление и очистка

**Убрать поле:**

```yaml
  - type: Item
    size: !Remove
```

**Убрать компонент целиком:**

```yaml
  - !Remove type: Light
```

**Убрать один элемент списка:**

```yaml
    tags:
    - !Remove Old
```

**Очистить список и заполнить заново:**

```yaml
    layers: !Clear
    - state: a
```

## Вставить элемент в конкретное место списка

```yaml
    tags:
    - !Index:0 New
```

`0` — первое место. Отрицательное число считает с конца.

## Изменить уже существующий элемент списка

Когда в списке объекты (например, слои спрайта), а менять нужно один из них, указываем его номер (с нуля):

```yaml
    layers:
    - !CombineIndex:1 state: new_state
```

## Порядок наложения

Если несколько заплаток меняют одно и то же поле, побеждает та, что применилась позже. Порядок такой:

1. Сначала загружаются обычные файлы.
2. Потом заплатки по номеру: `x.partial.yml` = 0, `x.partial.1.yml` = 1, `x.partial.2.yml` = 2 и т. д. Больше число — позже применится.
3. Внутри одного номера — по алфавиту путей файлов.

Чтобы твоя заплатка точно была последней, назови файл `x.partial.5.yml` (или другим большим номером).

## Частые ошибки

- Забыл `!PartialOnly` — при опечатке в `id` создастся новый «пустой» прототип.
- Положил partial-файл не в `_Maid` или назвал без `.partial.` — игра решит, что это дубликат, и выдаст ошибку `Duplicate ID`.
- Хочешь убрать и поставить одно поле в одном блоке — так нельзя, убери отдельно.
- Правка не применилась — проверь написание `id` и `type` и наличие оригинала.
- Положил в `Override` правку логики — туда можно только массовые замены звуков и текстур. Остальное пиши в `*.partial.yml` (см. `CONTRIBUTING.md`).
