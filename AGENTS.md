## Upstream Modification Conventions
- Everything in `_Maid/` folders is Maid-owned; edit freely without markers.
- Outside `_Maid/`, keep upstream modifications minimal and marked:
  - Small/inline: `// MAID {change}`
  - Block replacements: wrap with `// MAID BEGIN {change}` and `// MAID END {change}`, preserving old code commented out inside `/* ... */`.
  - YAML: use `#` comments per line.
  - Localization: no comments in `.ftl` files.
  - `{change}`: short, consistent 2–5 word task label.
- Prototype overrides (details: `.claude/docs/modularity/partial-prototypes.md`):
  - `Resources/Prototypes/_Maid/Override/` is only for mass-ported resource overrides (textures, sounds, etc. repointed to old-build assets, usually generated by the `asset-override` tool).
  - Any other override of an upstream prototype (damage, UI, console mode, etc.) goes in a `*.partial.yml` file (`*.partial.N.yml` for ordering) next to the new Maid content under `_Maid/`, not in `_Maid/Override/`.
- **NEVER** coauthor yourself in any way (i. e. commit message, comments or claude github account (git credentials already configured)).
